# F06【架空】みなと臨海工場　本作り（2004–2026 年度）

- 資料：full/files/（フラット）
- 正解：full/answer/files/<stem>.json、full/answer/world.json
- 担当者の説明：full/user.md
- 生成器と検査：full/gen/（`python3 run_full.py` で全部作り直し、`python3 check.py` で検査）

正解の世界は 1 本にしてある（gen/core.py）。機器ごとの年度の作業（world.simulate）を契約・停止期間・工程の項目・日・班に振り分け、その結果から工程表 → 日報 → 報告書 → 発注 → 計画 → 台帳を書き分けている。全部で 10,318 件の作業があり、実施済みのものはすべて、どこかの資料の行と結び付いている。結び付かない作業は world.json の unrecorded_works に理由を書いた（地元業者の補修 140 件、2026-11-13 時点で未実施の予定 160 件）。

### (3) 資料どうしの書き方の違い
- 同じ作業でも、資料によって呼び方と粒度が違う。工程表・日報は作業項目単位（例：「集じん器 点検整備（ダンパ・ロータリバルブ・コンベヤ）」）、報告書の記録表は機器 1 台ごと、計画は機器の星取、発注台帳は契約単位。
- 工程表の予定と実績のずれ（遅れ）は、日報の特記と報告書の所見に出る。主な遅れは次のとおり。
  - H21 の 3号炉：降雪で 1 日延長。
  - H25 の 1号炉：過熱器の吊り金具割れで 1 日延長。
  - R2 の 1号炉：協力会社の人員減で 2 日延長。
  - R4 の 2号炉：水冷壁管の補修工事（別契約）で復旧以降を 3 日繰下げた。再加熱器の施栓とろ布ケージの交換で、それぞれ 1 日延長。
- 前年度の報告書で「要注意（次年度 補修を提案）」とした機器は、翌年度の作業が「前年度指摘箇所 補修」になる（world.findings でつながる）。
- 年度の書き方：市の帳票は和暦（H31・R2 など）、延命化計画は西暦と和暦の併記、R1 からの CSV は西暦、メーカーの工程表・日報は和暦の日付。
- 業者名：CSV 旧は「汐見重工環境（株）」、CSV 新は「汐見重工環境株式会社」、汎用機 CSV は「汐見重工環境」、帳票は「【架空】汐見重工環境株式会社」。
- 地元業者の補修（港南工業・臨海プラント工事）は、発注台帳の契約行にしか出てこない。
- ろ布：H30 から市の物品購入（680 本、支給品）が CSV に出る。報告書では「市支給品（680 本）」と書き、予備 8 本を返納している。H29 以前は、報告書でメーカーが「当社手配」と書く。
- 基幹改良：CSV は契約総額・年割・前金払で出る。報告書は年度ごとの出来高報告、工程表と日報は年度ごとの改良停止期間の分。
- 見本（out/）の 3炉1枚工程表には「様式 H22（m2）」とあったが、プロファイル（工程表の担当 m1 2004–2012、様式の変更 2010）に合わせ、本作りでは「様式 H22（m1）」とした。
- 見本の契約の中身（R4 2号炉の日報の文など）は、本作りでは 1 本にした正解の世界から作り直している。様式は同じだが、文と人数は見本と一致しない。

## 合わせきれなかった点・未確定
- 法定点検の周期の確度は、見本の notes/05 のまま。ボイラ定期事業者検査の 2 年、第一種圧力容器の扱いは確度が低い。
- 日報の記事は、作業項目ごとの決まり文句に機器名・数値・出来事を当てはめて作っている。長い期間の日報では、同じ言い回しがくり返し出る。
- 地元業者の補修は、工期を作業の月から機械的に置いている。複数の作業を 1 契約にまとめた年は、工期が数か月にわたる。
- 1 か所に結び付いた作業でも、工程表・年間工程・日報・報告書の複数の行に重ねて出るので、world.json の links は 1 作業につき複数ある。
